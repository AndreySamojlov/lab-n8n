# Идеи развития

Дата: 2026-05-01. Статус: **living draft**.

Этот документ хранит идеи, которые уже достаточно конкретны, чтобы не теряться в переписке, но ещё не стали частью обязательного устава или проектного README.

## 1. ИИ в интерфейсе n8n

- Подключить ИИ прямо к интерфейсу n8n как помощника по canvas, паспортам и ошибкам.
- Сделать так, чтобы ИИ помогал не только писать workflow, но и объяснял, что именно сейчас видно на canvas.
- Дать ИИ контекст на уровне паспорта, названий нод и локальных фрагментов конфигурации, а не всей среды целиком.

## 2. Разбор ошибок нод без полной выгрузки flow

- Анализировать ошибки точечно по проблемной ноде, её паспорту и соседним связям.
- Не выгружать весь flow, если для диагностики достаточно паспорта, имени ноды, входного/выходного контракта и короткого фрагмента execution-лога.
- Собирать минимальный диагностический пакет: имя ноды, тип, note, контракт, текст ошибки, upstream/downstream контекст.

## 3. Потенциальные следующие шаги

- Подготовить прототип UI-слоя, где ИИ видит только выбранную ноду и связанные с ней паспортные данные.
- Определить формат локального diagnostic snapshot для ошибок без полного экспорта workflow.
- Согласовать, какие фрагменты данных можно передавать ИИ по умолчанию, а какие всегда требуют явного подтверждения пользователя.

## 4. Правило для пополнения

- Если идея становится устойчивой и повторяемой, переносим её в `CLAUDE.md`, `DESIGN.md`, проектный README или flow-doc.
- Если идея пока исследовательская, остаётся здесь до прояснения.
